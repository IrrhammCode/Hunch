### 3. Contract call vs transaction hash — Hunch must use the contract-call body

- **Claim:** The project-scoped `/simulate` endpoint takes an **unsigned transaction object** (like `eth_call`): `network_id`, `from`, `to`, `input` (encoded calldata), `gas`, optional `gas_price`/`value`/`block_number`/`simulation_type`/`save`. It does **not** take a live tx hash as the primary input. Any sender can be set in `from` because simulations are unsigned.  
  Existing on-chain hashes are inspected/debugged via the **dashboard Explorer / debugger** (paste hash), not via this pre-send REST body.  
  Hunch should populate `to` + `input` from ethers/viem `populateTransaction` for approve/commit/execute, then POST before broadcast.
- **Quote:** “The simulated payload is similar to the `eth_call` JSON RPC call. The fields below are required: `network_id` (string) … `to` … `from` … `input` … `gas`.” … “Since Tenderly simulates *unsigned* transactions, you don't need to own an account's private key to simulate transactions from a specific sender.”
- **URL:** https://docs.tenderly.co/simulations/single-simulations
- **Date:** 2026-09-18
- **Confidence:** High

### 4. Simulate endpoint format (exact)

- **Claim:** Two project-scoped formats:

  **Public network (Hunch Monad testnet path):**
  ```
  POST https://api.tenderly.co/api/v1/account/${TENDERLY_ACCOUNT_SLUG}/project/${TENDERLY_PROJECT_SLUG}/simulate
  Header: X-Access-Key: ${TENDERLY_ACCESS_KEY}
  Header: content-type: application/json
  Body: { "network_id": "10143", "from": "0x…", "to": "0x…", "input": "0x…", "gas": …, "simulation_type": "full"|"abi"|"quick" }
  ```

  **Virtual Environment (optional staging path):**
  ```
  POST https://api.tenderly.co/api/v1/account/${TENDERLY_ACCOUNT_SLUG}/project/${TENDERLY_PROJECT_SLUG}/vnets/{vnetId}/transactions/simulate
  ```

  **Node RPC alternative** (same key family, different env name):
  ```
  POST https://monad-testnet.gateway.tenderly.co/${TENDERLY_NODE_ACCESS_KEY}
  JSON-RPC method: tenderly_simulateTransaction
  params: [ { from, to, gas, value, data }, "latest" ]
  ```
- **Quote:** “Simulation API endpoint on public network” → `https://api.tenderly.co/api/v1/account/${TENDERLY_ACCOUNT_SLUG}/project/${TENDERLY_PROJECT_SLUG}/simulate` … “on a Virtual Environment” → `…/vnets/{vnetId}/transactions/simulate`
- **URL:** https://docs.tenderly.co/simulations/single-simulations
- **Date:** 2026-09-18
- **Confidence:** High

### 7. VNET vs Pro / public simulation — what Hunch should use

- **Claim:**
  - **Public-network Simulation API / RPC** (`/simulate` or `tenderly_simulateTransaction` on `network_id` 10143): dry-run approve/commit/execute against latest Monad testnet state. Correct primary path for Hunch pre-broadcast checks.
  - **Virtual Environments (VNET)**: isolated forked/staging chains with faucet, state overrides, explorer; simulate via VNET RPC or `…/vnets/{vnetId}/transactions/simulate`. Better for CI/staging than for per-tx production guards on live testnet.
  - **Pro / Console**: unlocks Simulation API, VNET, Node RPC, access tokens. Free = debugger + UI single-tx preview only.
  - Docs recommend Simulation **RPC** for VNET work, but REST `/simulate` remains valid for public networks.
- **Quote:** “Note: Generating API access tokens and using the Tenderly API are available on the paid plan.” … Free: “No API access on Free.” … Console/Pro Simulator includes “Simulation API for CI/CD, scripts, and bots” + “Virtual Environments”. VNET page: “We recommend integrating the Simulation RPC, but it's possible to use Simulation REST API.”
- **URL:**

  - https://docs.tenderly.co/virtual-environments/interact/simulate-transactions
